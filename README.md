# Pairs Trading Strategy Demo (MEXC API)

Фронтенд на одном PHP‑файле (`index.php`), который:

1. Подтягивает свечи для двух торговых пар с публичного REST API MEXC (`/api/v3/klines`).
2. Выравнивает данные по общим временным меткам.
3. Рассчитывает отношение цен `B/A`, скользящее среднее, стандартное отклонение и динамические полосы ±σ.
4. Строит сигналы входа/выхода и отображает статистику по сделкам.

Проект создан как иллюстрация «Гипотезы 2» из переписки.

---

## Требования

* PHP 8.1+ (желательно 8.2 и выше).
* Включённый `cURL` (расширение `ext-curl`) или разрешённый `allow_url_fopen`.
* Доступ к интернету для запросов к `https://api.mexc.com`.

---

## Быстрый старт

1. Разместите содержимое каталога на веб-сервере (например, Nginx + PHP-FPM, Apache или встроенный PHP-сервер).
2. Откройте страницу `index.php` в браузере.
3. При необходимости задайте параметры через форму и нажмите «Пересчитать».

## Настраиваемые параметры

| Параметр       | Где задаётся                   | Назначение                                                                 | Значение по умолчанию |
|----------------|--------------------------------|-----------------------------------------------------------------------------|------------------------|
| `symbolA`      | Поле формы / `?symbolA=BTCUSDT` | Тикер в знаменателе (базовый актив).                                       | `BTCUSDT`              |
| `symbolB`      | Поле формы / `?symbolB=ETHUSDT` | Тикер в числителе (котируемый актив).                                      | `ETHUSDT`              |
| `interval`     | Выпадающий список               | Интервал японских свечей MEXC (поддерживаются `1m`, `5m`, `15m`, `1h`, `4h`, `1d`, `1w`). | `1d` |
| `lookback`     | Поле формы / query string       | Длина окна скользящего среднего и σ. Минимум — 2.                           | `30`                   |
| `sigma`        | Поле формы / query string       | Множитель σ для торговых полос (аналог Боллинджера).                       | `2.0`                  |
| `limit`        | Поле формы / `?limit=200`       | Количество свечей, загружаемых на каждую пару (ограничение API — до `1000`). Должно быть > `lookback`. | `120` |

### Как это влияет на стратегию

* **symbolA / symbolB** — определяют отношение `Цена(symbolB) / Цена(symbolA)`. Для гипотезы из переписки использовались `ETHUSDT` / `BTCUSDT`, что даёт динамику ETH/BTC.
* **interval** — чем мельче интервал, тем больше шум и потенциальных сигналов; дневные свечи (`1d`) используются для «длинной» стратегии.
* **lookback** — размер окна, в котором считается среднее и стандартное отклонение. При увеличении окна сигналы появляются реже, но референсное значение устойчивее.
* **sigma** — ширина торговых полос. `2σ` даёт классические «крайние» точки, `3σ` уменьшит частоту входов, `1.5σ` сделает их чаще.
* **limit** — глубина истории. Чем больше, тем больше данных (но не стоит брать слишком много на коротких интервалах, чтобы не упереться в лимиты API).

## Пример запросов

* Отношение ETH/BTC на дневных свечах, как в описании:
  ```
  /index.php?symbolA=BTCUSDT&symbolB=ETHUSDT&interval=1d&lookback=30&sigma=2&limit=120
  ```

* Пятиминутные свечи для пары SOL/BTC:
  ```
  /index.php?symbolA=BTCUSDT&symbolB=SOLUSDT&interval=5m&lookback=50&sigma=2.5&limit=500
  ```

## Добавление своих примеров

1. Задайте нужные параметры через форму.
2. Сделайте скриншоты таблиц (сводка, сделки, дневной расчёт).
3. Добавьте секцию в `README` или отдельный `.md` с описанием сценария:
   * Какие символы.
   * Интервал и окно.
   * Полученный сигнал (вход/выход, P&L).
   * Ассумпции по торговому плану (тейк, стоп).

При желании можно дополнительно реализовать экспорт CSV/JSON из `$results` — логика уже собрана в массив, достаточно сериализовать перед выводом.

## Ограничения и «TODO»

* Используются только публичные эндпоинты MEXC, без авторизации и подписей.
* Нет асинхронного кеширования — при каждом обновлении данные запрашиваются заново.
* Не добавлены тесты (unit/e2e) — если планируется production, имеет смысл вынести логику в отдельные классы и покрыть их тестами.
* В портфеле не учитываются комиссии, размер позиции и плечо (PnL — относительный в % по отношению к входному ratio).
